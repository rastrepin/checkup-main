# Перевірка сайту після злиття

`prod-check.mjs` перевіряє сторінки так, як їх бачить пацієнт:

1. **Заявка «Мій план»** – обирає клініку, додає одне дослідження з ціною, відправляє тестову заявку і звіряє:
   дані пацієнта на місці; сума в заявці = сума на сторінці = сума цін послуг у базі; кожне показане дослідження
   є серед послуг заявки; усі послуги – обраної клініки.
2. **Заявка з картки програми клініки** – назва і ціна програми в заявці = на картці.
3. **Посилання** – усі посилання сторінки відкриваються, 404 немає (внутрішні 4xx/5xx – помилка, зовнішні – попередження).

## Тестові заявки не йдуть клінікам

Заявка відправляється з номером **+380 00 000 00 00**. `app/api/leads/route.ts` пише її в `leads` зі `status = 'test'`,
клініці не передає, а в контрольний чат шле з позначкою «🧪 Тест автоперевірки» і переліком послуг із сумою.
Перед відправкою скрипт питає `GET /api/leads`; якщо сайт не повідомляє тестового режиму (старий код на проді),
заявки не відправляються, перевіряються лише показані суми і посилання.

## Коли запускається

`.github/workflows/qa-after-deploy.yml` – після кожного готового деплою Vercel:
- production → погоджені сторінки (`lib/seo/approved-routes.json`) на https://check-up.in.ua;
- прев'ю → усі вікові сторінки міст (з `?drafts=1`), лише якщо в секретах репозиторію є `VERCEL_AUTOMATION_BYPASS_SECRET`.

Звіт – у Summary запуску в GitHub Actions і в артефакті `qa-report` (з знімками сторінок з помилками).
Вручну: Actions → «Перевірка після деплою» → Run workflow (після злиття файлу в `main`).

## Локально

```
cd scripts/qa && npm install && npx playwright install chromium
node prod-check.mjs --base https://check-up.in.ua
node prod-check.mjs --base <адреса прев'ю> --all-city-pages --drafts   # з VERCEL_AUTOMATION_BYPASS_SECRET
node prod-check.mjs --base <адреса> --routes /ukr/female-checkup/do-30-rokiv/kharkiv --no-submit
```
