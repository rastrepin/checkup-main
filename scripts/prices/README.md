# Оновлення цін клініки з таблиці цін

Джерело цін — Google Таблиця, де клініка вносить нові ціни з датою, з якої вони діють. Сайт читає ціни з бази (сторінки оновлюються з бази щогодини), тому досить оновити базу.

## Як це працює

1. Аркуш «ОНКЛІНІК ціни» з таблиці зберігається як CSV (Файл → Завантажити → CSV). Рядки назви й примітки над заголовком скрипт пропускає сам; дані закінчуються першим порожнім ID. Рядки без «Нової ціни» не змінюються.
2. `sync-prices.mjs` зіставляє рядки з базою і друкує звіт: що оновиться, що чекає своєї дати, що потребує рішення.
3. Після перевірки звіту той самий запуск з `--apply` записує ціни в базу.

Що скрипт ніколи не застосовує сам (іде в «потребує рішення»):
- код, якого немає в базі;
- ціна не число, нуль, або без дати «діє з»;
- зміна більше ніж на 30% (поріг — `--max-change-pct`);
- дата старіша за чинну ціну.

## Ключі зіставлення

| Колонка «Ключ БД» | Що оновлюється |
|---|---|
| `program:<slug>` | `checkup_programs`: ціна зі знижкою = «Нова ціна», ціна без знижки = «Ціна без знижки» |
| `service:<код>` або порожньо | `clinic_services` за кодом клініки і містом (суфікс `-OH` у кодах ОН Клінік ігнорується) |

Ключ береться з колонки «Ключ БД», якщо її немає — з файлу `--map` за службовим ID рядка (`{"KH-001": "program:zhinochyi-pislya-40"}`), якщо й там немає — з «Коду послуги ОНКЛІНІК». Рядок без жодного ключа йде в «потребує рішення».

Якщо в таблиці немає «ціни без знижки», закреслена ціна програми зберігає ту саму пропорцію до ціни, що й зараз; звіт показує нову закреслену ціну.

Назви колонок таблиці — у `columns.json`.

## Запуск

```
# перевірка (нічого не змінює)
node scripts/prices/sync-prices.mjs --clinic onclinic-kharkiv --city kharkiv --csv prices.csv --map map-kharkiv.json

# запис у базу після перевірки
SUPABASE_URL=... SUPABASE_SERVICE_ROLE_KEY=... node scripts/prices/sync-prices.mjs --clinic onclinic-kharkiv --city kharkiv --csv prices.csv --apply
```

`--today YYYY-MM-DD` — дата, на яку застосовувати (за замовчуванням сьогодні за Києвом). `--db-json` — перевірка на знімку бази без мережі.

# Інструмент оновлення цін: від прайсу клініки до сайту і бази

Три кроки, кожен окремим скриптом. Жоден не змінює базу чи Tilda сам: запис у базу — лише `sync-prices.mjs --apply` після погодження, Tilda — вручну за `tilda-manual.csv`.

| Крок | Скрипт | Вхід | Вихід |
|---|---|---|---|
| 1. Приймання | `intake.py` | файли клініки (xlsx або CSV вкладки) | прайс у єдиному форматі, CSV |
| 2. Порівняння | `compare.py` | єдиний прайс, попередній прайс, знімок бази, конфіг клініки | `report.xlsx` (було → стало), `db-update.csv`, `tilda-manual.csv`, `plan.json` |
| 3. Запис у базу | `sync-prices.mjs` | `db-update.csv` | звіт; з `--apply` — оновлені ціни в базі |

## Конфіг клініки

`clinics/<slug>.json` — усе, що відрізняє одну клініку від іншої:

- `sources` — звідки брати прайс: вкладка, колонки, перший рядок, кольори позначок «змінено».
- `kind_rules` — як визначити вид позиції (консультація, діагностика, аналіз, процедура) за розділом і назвою.
- `checkup_discount_pct`, `site_price_rule` — знижки check-up і чи показувати їх на сайті.
- `max_change_pct` — поріг: зміна більша за нього не потрапляє у файли для запису, а йде в «Потребує рішення».
- `targets` — словник відповідностей: який лікар на сайті (SKU Tilda) якою послугою прайсу оцінюється, який чекап — якою позицією, яка програма в базі (slug) — якою позицією, і склад програм за віком з цінами складових, за якими рахована поточна ціна.

Позиції прайсу зіставляються ключем «розділ|назва» (нормалізовано): кодів у прайсах ОН Клінік немає, а одна назва трапляється в різних розділах з різною ціною. Якщо позицію з конфігу в новому прайсі не знайдено (перейменували), звіт показує найближчі назви, а лікар чи програма йдуть у «Потребує рішення».

## Запуск (приклад Черкас)

```
python3 scripts/prices/intake.py --config scripts/prices/clinics/onclinic-cherkasy.json \
  --file services=services.xlsx --file checkups=checkups.csv \
  --source-date services=2026-10-28 --source-date checkups=2026-10-21 --out 2026-11-03.csv

python3 scripts/prices/compare.py --config scripts/prices/clinics/onclinic-cherkasy.json \
  --intake 2026-11-03.csv --previous 2026-10-26.csv --db-json db.json \
  --valid-from 2026-11-03 --out-dir runs/2026-11-03

node scripts/prices/sync-prices.mjs --clinic onclinic-cherkasy --city cherkasy --csv runs/2026-11-03/db-update.csv
```

Потрібен Python 3 з `openpyxl`. Знімки прайсів і звіти зберігаються поза репозиторієм (спільна тека проекту), щоб наступне оновлення порівнювалось з попереднім.
